# Ray Tracer

Проект на C++, в рамках которого реализован рейтрейсер для рендеринга простых 3D-сцен, заданных в формате `.obj`. Проект включает геометрические примитивы и вычисление пересечений, чтение сцен и материалов, отладочные режимы визуализации, а также полноценный рендеринг с освещением, тенями, отражениями и преломлениями.

## Структура проекта


| Модуль | Описание |
|---|---|
| `raytracer-geom` | Векторная математика, геометрические примитивы и алгоритмы пересечения лучей с объектами. |
| `raytracer-reader` | Чтение сцен из `.obj`-файлов и материалов из `.mtl`-файлов. |
| `raytracer-debug` | Упрощённые режимы рендеринга для проверки геометрии, камеры и трассировки. |
| `raytracer` | Основной алгоритм трассировки лучей и формирование изображения. |


## Геометрия (`raytracer-geom`)

Модуль реализует математические структуры и операции, необходимые для трассировки лучей.


### Вектор

`Vector` — трёхмерный вектор, координаты которого хранятся в `std::array`. Реализованы базовые векторные операции, в том числе:

- скалярное произведение (`DotProduct`);
- векторное произведение (`CrossProduct`);
- вычисление длины (`Length`).

### Геометрические примитивы

- **Triangle** — треугольник, заданный тремя вершинами; площадь вычисляется через векторное произведение.
- **Ray** — луч, заданный началом и нормализованным направлением.
- **Sphere** — сфера с центром и радиусом.
- **Intersection** — данные о пересечении: точка, нормаль и расстояние от начала луча.


### Геометрические алгоритмы

- `GetIntersection` — поиск пересечения луча с треугольником или сферой. При отсутствии пересечения возвращается `std::nullopt`. Для треугольников используется алгоритм Мёллера — Трумбора.
- `Reflect` — вычисление направления отражённого луча.
- `Refract` — вычисление направления преломлённого луча с учётом отношения показателей преломления сред.
- `GetBarycentricCoords` — вычисление барицентрических координат точки относительно треугольника; используются, в частности, для интерполяции нормалей.


## Чтение сцены (`raytracer-reader`)

Сцена считывается из `.obj`-файла. Парсер сохраняет вершины, нормали, геометрические объекты, источники света и материалы. Геометрические объекты связываются с материалами, хранящимися в сцене, без копирования самих материалов.


### Поддерживаемые записи OBJ

| Запись | Назначение |
|---|---|
| `v` | Координаты вершины. |
| `vn` | Вектор нормали вершины. |
| `f` | Грани. Грани с произвольным числом вершин разбиваются на треугольники. |
| `mtllib` | Подключение файла материалов `.mtl`. |
| `usemtl` | Выбор материала для последующих объектов. |
| `S x y z r` | Дополнительная запись сферы с центром `(x, y, z)` и радиусом `r`. |
| `P x y z r g b` | Дополнительная запись точечного источника света с координатами и интенсивностью `(r, g, b)`. |

Поддерживаются варианты записи индексов вершин в `f`, включая индексы текстур и нормалей, а также их пропуски. Текстурирование при этом не реализуется. Индексы сущностей в гранях относятся к общему массиву сущностей OBJ.

Порядок объектов и источников света соответствует порядку их появления в исходном файле.


### Материалы (MTL)

Из файлов `.mtl` считываются следующие параметры:

| Параметр | Значение |
|---|---|
| `newmtl` | Название материала. |
| `Ka` | Ambient color — окружающая составляющая. |
| `Kd` | Diffuse color — диффузная составляющая. |
| `Ks` | Specular color — зеркальная бликовая составляющая. |
| `Ke` | Intensity — дополнительная эмиссионная составляющая, учитываемая аналогично `Ka`. |
| `Ns` | Specular exponent — степень бликовой составляющей. По умолчанию `1`. |
| `Ni` | Refraction index — показатель преломления. По умолчанию `1`. |
| `al` | Albedo — коэффициенты отражения, преломления и локального освещения. По умолчанию `(1, 0, 0)`. |

Остальные параметры MTL игнорируются. Если материал не задаёт `al`, используется значение `(1, 0, 0)`.


## Отладочные режимы (`raytracer-debug`)

Отладочная часть предназначена для проверки камеры, геометрии и работы трассировки без полноценного расчёта освещения.


### Depth

В режиме `RenderMode::kDepth` цвет пикселя определяется расстоянием `d` до ближайшего пересечения. После нормализации относительно максимального расстояния `D` в сцене:

\[
C = (d/D,\ d/D,\ d/D)
\]
Если луч не пересекает объекты, пиксель окрашивается в белый цвет `(1, 1, 1)`.

### Normal

В режиме `RenderMode::kNormal` цвет определяется нормалью в ближайшей точке пересечения. Нормаль ориентируется против направления луча, а её компоненты из диапазона `[-1, 1]` переводятся в `[0, 1]`:

\[
C = (N + 1)/2
\]
Если пересечения нет, используется чёрный цвет `(0, 0, 0)`.


## Основной рейтрейсер (`raytracer`)

Основной модуль реализует рендеринг сцены в режиме `RenderMode::kFull`. Точка входа в интерфейс рендеринга — функция:

```cpp
Image Render(
    const std::filesystem::path& path,
    const CameraOptions& camera_options,
    const RenderOptions& render_options
);
```

- `path` — путь к `.obj`-файлу сцены;
- `camera_options` — параметры камеры, разрешение изображения и направление взгляда;
- `render_options` — настройки рендеринга, включая глубину рекурсии и режим.

### Алгоритм рендеринга

1. Считать сцену из OBJ-файла и загрузить материалы.
2. Настроить положение и ориентацию камеры.
3. Для каждого пикселя сформировать луч, проходящий через центр пикселя экрана.
4. Найти ближайшее пересечение луча со сценой.
5. Рассчитать освещение в точке пересечения.
6. При необходимости рекурсивно трассировать отражённые и преломлённые лучи.
7. Сохранить вычисленный цвет пикселя.
8. Выполнить tone mapping и gamma correction для итогового изображения.

Если луч не пересекает объекты сцены, используется цвет фона.


## Камера

Камера задаётся положением `look_from` и точкой, на которую она направлена, `look_to`. По умолчанию она расположена в начале координат и смотрит вдоль отрицательной оси `Z`.


- Фокусное расстояние фиксировано и равно `1`.
- Вертикальный угол обзора задаётся параметром `fov`.
- Горизонтальный угол обзора определяется соотношением сторон изображения.
- Ось `Y` направлена вверх, ось `X` — вправо.
- Лучи проходят через центры пикселей.

Для преобразования лучей из пространства камеры в мировое используется преобразование camera-to-world, построенное с учётом направления взгляда камеры.


## Освещение

Для вычисления освещённости используется модель Фонга, включающая ambient, diffuse и specular составляющие.


### Диффузная составляющая

Для каждого источника света:

\[
D_i = I \cdot \max(0, \mathbf{v_l} \cdot \mathbf{n})
\]

где `I` — интенсивность света, `v_l` — направление от точки пересечения к источнику, `n` — нормаль поверхности.

### Бликовая составляющая

\[
S_i = I \cdot \max(0, \mathbf{v_r} \cdot \mathbf{v_{lr}})^{N_s}
\]

где `v_r` — направление взгляда, `v_lr` — отражённое направление света, `Ns` — параметр материала, определяющий выраженность блика.

### Суммарное освещение

Локальная составляющая освещения вычисляется с учётом параметров материала:

\[
I_{local} = al_0 \cdot (K_d \sum D_i + K_s \sum S_i) + K_a + K_e
\]

Если между точкой поверхности и источником света находится другой объект, источник не вносит вклад в освещение этой точки (тень).


## Отражения и преломления

Рейтрейсер поддерживает рекурсивную трассировку лучей для отражающих и прозрачных материалов. Глубина рекурсии ограничивается параметром `depth`.


### Отражение

Для отражающего материала (коэффициент `al_1` отличен от нуля) и луча, находящегося снаружи объекта, вычисляется отражённый луч. Цвет, полученный при рекурсивной трассировке, умножается на коэффициент отражения материала и добавляется к итоговому цвету.

### Преломление

Для прозрачного материала (коэффициент `al_2` отличен от нуля) трассируется преломлённый луч. При переходе из объекта показатель преломления `Ni` учитывается в обратном направлении; для внешней среды он равен `1`. Внутри объекта прозрачность принимается равной `1`, а отражённый луч не вычисляется. Снаружи вклад преломления умножается на коэффициент `al_2`.

### Итоговый цвет

\[
I = al_0 (K_d \sum D_i + K_s \sum S_i) + K_a + K_e + al_1 I_{reflect} + al_2 I_{refract}
\]

Для вторичных лучей используется небольшое смещение от поверхности (`kEps`), чтобы избежать повторного пересечения с той же точкой из-за погрешностей вычислений.


## Постобработка

После вычисления цветов всех пикселей выполняются два этапа.


### Tone Mapping

Интенсивность RGB может выходить за диапазон `[0, 1]`. Для приведения значений к диапазону изображения сначала определяется максимальное значение `C` среди всех RGB-компонент изображения, затем применяется преобразование:

\[
V_{out} = \frac{V_{in}(1 + V_{in}/C^2)}{1 + V_{in}}
\]

### Gamma Correction

Для преобразования линейного RGB в значения, используемые при сохранении изображения, применяется гамма-коррекция:

\[
V_{gamma} = V_{out}^{1/2.2}
\]

После этого значения RGB умножаются на `255` и преобразуются в целочисленный формат для записи изображения.


## Сборка и тестирование

Для сборки окружения на Ubuntu требуется библиотека PNG:

```bash
sudo apt-get install libpng-dev
```

На macOS:

```bash
brew install libpng
```

Тесты сравнивают изображения, полученные рейтрейсером, с эталонными изображениями на одинаковых входных сценах. Для запуска отдельного теста можно использовать фильтр Catch2, например:

```bash
./test_raytracer_asan "Box with spheres"
```

Решение проверяется в конфигурациях `Asan` и `RelWithDebInfo`; часть тестов запускается только в определённых конфигурациях.
